# T-01 — Infraestructura Docker
**Agente:** dev-infra · **Contrato:** §1, §2, §9 (pytest.ini), §10
**Objetivo:** `docker compose up` levanta qdrant → ingest → app en macOS arm64, Windows y Linux.
**Archivos permitidos:** `docker-compose.yml`, `Dockerfile`, `.dockerignore`, `.env.example`, `.gitignore`, `requirements.txt`, `pricing.yaml`, `pytest.ini`, `.github/workflows/ci.yml`, `tests/test_infra_*.py`
**Notas:** `requirements.txt` con versiones exactas (qdrant-client 1.20.0, fastembed 0.9.1, streamlit 1.67.0, langgraph 1.2.20, pandas, pyarrow, httpx, pyyaml, pytest, altair). `pricing.yaml` con 3 referencias editables y nota "precios de referencia, editar". CI: build de la imagen + `docker compose run --rm app pytest`.
**Criterio de hecho:**
1. `docker compose config` sin errores con `.env` copiado de `.env.example`.
2. `docker compose build` termina y la imagen contiene ambos modelos en `/models` (verificar con `docker compose run --rm --no-deps app python -c "..."` cargando los modelos sin red).
3. `docker compose up -d qdrant` → healthy; `curl localhost:6333/collections` sin clave → 401/403; con `api-key` → 200.
4. Ninguna imagen usa `latest`.
