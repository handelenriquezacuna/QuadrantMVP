# T-13 — Ollama contenedor sin puerto en el host
**Agente:** dev-infra · **Contrato:** §2 (profile `llm`), §10
**Objetivo:** que el contenedor `ollama` y un Ollama nativo puedan coexistir.
**Archivos permitidos:** `docker-compose.yml`, `README.md` (solo sección Ollama y solución de problemas), `tests/test_infra_*.py`
**Criterio de hecho:**
1. El servicio `ollama` no tiene `ports:`; `app` y `ollama-pull` lo siguen alcanzando en `http://ollama:11434`.
2. Con Ollama nativo escuchando en el host:11434, `docker compose --profile llm up -d ollama ollama-pull` arranca sin error de puerto y `ollama-pull` termina con 0.
3. README: aclara que `ollama` en la terminal del host habla con el Ollama nativo, no con el contenedor; para el contenedor se usa `docker compose exec ollama ollama ...`.
