# T-10 — Ollama como servicio opcional de compose
**Agente:** dev-infra · **Contrato:** §1, §2 (profile `llm`), §10
**Objetivo:** `docker compose --profile llm up` levanta Ollama en contenedor, descarga el modelo de `.env` y la app lo usa, sin Ollama en el host.
**Archivos permitidos:** `docker-compose.yml`, `.env.example`, `README.md` (solo secciones de Ollama/requisitos/arranque/diagrama/solución de problemas), `tests/test_infra_*.py`
**Criterio de hecho:**
1. `docker compose config -q` pasa con y sin `--profile llm`.
2. Sin profile: `docker compose up -d` arranca qdrant, ingest y app (no intenta levantar ollama).
3. Con profile: `ollama` healthy, `ollama-pull` termina con código 0 y `ollama list` dentro del contenedor muestra el modelo; desde el contenedor `app`, `python -c "from app.soporte.ollama import disponible; print(disponible())"` imprime `True`.
4. README documenta ambos caminos (contenedor con `--profile llm` y Ollama nativo cambiando `OLLAMA_URL`), el tamaño de descarga aproximado del modelo, y que en Mac el contenedor usa CPU.
5. Ninguna imagen con `latest`.
