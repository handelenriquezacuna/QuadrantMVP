PRÁCTICA No.3 · BASES DE DATOS NoSQL

Qdrant Lab: del cero al MVP

Qué es una base de datos vectorial, cómo está armado el MVP y qué mostrar en cada uno de los 4 minutos de la demo, con los números medidos que hay que señalar.

1 · QUÉ ES QDRANT

Una base de datos que busca por significado

Qdrant es una base de datos NoSQL de código abierto especializada en vectores. Una base relacional busca filas que coinciden con un valor exacto; Qdrant busca los puntos más parecidos a una consulta.

Para eso, un modelo de embeddings convierte cada texto en una lista de números (aquí, 384). Textos con significado parecido quedan cerca en ese espacio, aunque estén en idiomas distintos o no compartan ninguna palabra.

2 · VOCABULARIO

Ocho conceptos que aparecen en la demo

COLECCIÓN

Como una tabla

Conjunto de puntos con la misma configuración. El MVP usa faq_kb (3,000 FAQs) y answer_cache (respuestas ya generadas).

VECTOR DENSO

Significado

Encuentra textos parecidos aunque no compartan palabras ni idioma.

VECTOR DISPERSO

Palabras clave (BM25)

Acierta con términos exactos como números de pedido o nombres propios.

PAYLOAD + ÍNDICE

Filtros

Datos JSON del punto. Con índices sobre category e intent se filtra durante la búsqueda vectorial.

HÍBRIDA + RRF

Lo mejor de ambos

Corre denso y BM25 y fusiona los rankings con Reciprocal Rank Fusion en una sola consulta.

RECOMENDACIÓN

Más como esto

Busca puntos cercanos a ejemplos positivos y lejos de los negativos.

HNSW + CUANTIZACIÓN

Velocidad y memoria

HNSW es un grafo que evita comparar contra todo. La cuantización int8 guarda cada número en 1 byte en vez de 4.

API KEY

Seguridad

Sin la clave, Qdrant responde 401 y no entrega datos.

3 · ARQUITECTURA

Cómo está armado el MVP

Todo corre con docker compose up en Mac, Windows o Linux, con Docker Desktop como único requisito. El LLM es opcional y tiene dos caminos.

4 · EL CASO REAL

Un asistente de soporte que gasta menos tokens

La pestaña 5 compara dos formas de responder un ticket. Sin Qdrant, el LLM tiene que leer muchas FAQs en cada pregunta. Con Qdrant, la base hace el trabajo barato: reconoce preguntas ya respondidas y elige solo 3 FAQs relevantes.

7 · PONERLO A CORRER

Tres comandos y dos caminos para el LLM

git clone https://github.com/handelenriquezacuna/QuadrantMVP.git
cd QuadrantMVP && cp .env.example .env      # Windows: copy .env.example .env
docker compose up
OPCIÓN A · SIN INSTALAR NADA

Ollama en contenedor

docker compose --profile llm up. La primera vez descarga llama3.2:3b (~2 GB) y corre en CPU. Avance con docker compose logs -f ollama-pull.

OPCIÓN B · RECOMENDADA PARA EXPONER

Ollama nativo

Instalar Ollama, ollama pull llama3.2:3b y en .env poner OLLAMA_URL=http://host.docker.internal:11434. Usa la GPU de la Mac.

ANTES DE EXPONER
  • Levantar el stack una vez antes de la clase para que la descarga de imágenes y modelos ya esté hecha.
  • Dejar Ollama nativo corriendo y hacer una consulta de prueba en la pestaña 5 para cargar el modelo en memoria (la primera tarda más).
  • Justo antes de empezar, pulsar Vaciar caché en la pestaña 5 para que la primera pregunta falle y la paráfrasis acierte frente al público.
  • Al hacer scroll en la pestaña 5, mantener el cursor fuera de los gráficos: la rueda les hace zoom.
  • Tener abierto http://localhost:6333/dashboard por si preguntan cómo se ven las colecciones por dentro.
  • Sin LLM, la pestaña 5 muestra el benchmark grabado: la demo funciona igual.
